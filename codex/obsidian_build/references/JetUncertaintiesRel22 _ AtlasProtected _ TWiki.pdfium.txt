Tool requirements and assumptions
This page details the recommended Jet Energy Scale (JES) and Resolution (JER) uncertainty schemes available for use in R22 physics analyses.
Below, many details about specific aspects of the JES and JER uncertainties are provided in order to help users avoid common problems.
We recommend strongly that everyone performing ATLAS physics analyses with jets reads this page before starting their analysis!
R22 JES Pre-Recommendations
Preliminary jet calibrations and uncertainties are available for EMPFlow jets in R22 data and simulation. Different calibrations are available for Run 2 conditions
(2015/16/17/18 data and MC20a/d/e) and Run 3 conditions (2022/23 and MC23a/c) high-µ data (re)processed with R22.
This 'pre-recommendation' consists of a dedicated MC20 (MC23)-based calibration for Run-2 (Run-3) (area subtraction, pileup residual, absolute JES and Global
Sequential Calibration) and applies the R21 in situ calibration to all data reprocessed with R22+. The uncertainties associated with that calibration are provided to the user,
in the CategoryReduction and either SimpleJER or FullJER scheme.
These uncertainties are only supported in Release 22.2.108+
There are presently no calibrations or uncertainties for LCTopoJets or CSSKUFOJets reconstructed in R22 with any jet radius parameter. For EMTopoJets a dedicated set
of recommendations was derived by Long Lived Particles physics analyses team members. The calibration strategy does not include the Global Sequential Calibration step
and the uncertainties were derived following a similar procedure as the one used for R=0.4 particle-flow jet.
JetEtMiss does not currently support MC2MC corrections or per-jet flavour treatment for R22 pre-recommendations, but hopes to include these improvements again in future
calibrations. If the sensitivity of your analysis is limited by JES/JER/JMS/JMR performance, we encourage analysis teams to study the JetEtmissHighPriorityTasks page and
contact the JetEtMiss conveners to get involved!
How to correlate Run2 and Run3 pre-recommendations
For pre-recommendations, the NPs are mostly coming from the same in-situ measurement performed with Run2 data, so NPs with the same name should be treated as fully
correlated. The only exceptions are:
InSitu _NonClosure_PreRec
EtaIntercalibration _NonClosure_R10_PreRec
InSitu _NonClosure_R10_PreRec
AF3 components
Only the Category scheme is available for pre-recommendations, so this scheme should be used consistently in the input results. More schemes are foreseen to be available
in the next set of recommendations.
How to correlate small-R and large-R pre-recommendations
The method to correlate small-R and large-R JES/JER is the same as in release 21, documented in this Twiki.

Overview
The JES uncertainties come from several primary sources. They are:
Relative in situ
Dijet eta-intercalibration: calibrate the scale of forward jets with respect to central jets
Depends on jet pT and eta
More relevant for more forward jets
Absolute in situ
Z+jet balance: calibrate the scale of jets with respect to a well understood object (Zee, Zµµ)
Ddepends on jet pT
Mostly relevant for low pT
(below roughly 100 GeV)
Photon+jet balance: calibrate the scale of jets with respect to a well understood object (photon)
Depends on jet pT
Mostly relevant for medium pT
(from roughly 100 GeV to 1 TeV)
Multijet balance: calibrate the scale of jets with respect to a well understood object (a recoil system of lower-pT
, calibrated jets)
Depends on jet pT
Mostly relevant for high jet pT
(from roughly 1 TeV to 2 TeV)
Single-hadron response and test beam uncertainties
Depends on jet pT
Mostly relevant for extremely high jet pT
(above the end of the multi-jet balance, ~2 TeV)
Pileup uncertainties
Depend on jet pT
, jet eta, NPV and mu (exact variables depend on the uncertainty component)
Mostly relevant for low jet pT
(below roughly 50 GeV)
Flavour-related uncertainties
Depend on at least jet pT and jet eta, perhaps more

Depends on whether or not the user specifies their own flavour composition ()
Depends on whether or not that flavour composition is specified by jet multiplicity ()
Depends on whether or not that jet multiplicity flavour composition is specified by process ()

(below several hundred GeV)
Punch-through uncertainty
Depends on jet pT

Jet energy resolution (JER) uncertainties : background information
Overview
The JER uncertainties come from a few primary sources. They are:
Data vs MC difference
Depends on pT and eta
Derived to account for differences between the nominal MC and data JER
If MC is better than data, we smear the MC to match data
If data is better than MC, we don't want to degrade the data to match a given MC
This uncertainty is only non-zero when the nominal data resolution is superior to the nominal MC resolution
This uncertainty differs depending on if you have configured the tool using MC20 or MC21 (fullsim) or AFII (fastsim)
The resulting uncertainty name also differs to reflect this (e.g. JET_JER_DataVsMC_MC20 vs JET_JER_DataVsMC_AFII)
If you are using both fullsim and fastsim samples, then these two components should be treated separately
Noise term evaluation from random cones in zero bias data
Depends on pT and eta
Mostly relevant for low pT (below 100 GeV)
In situ dijet pT balance asymmetry
Depends on pT and eta
Relevant almost everywhere (from a few tens of GeV to the highest pT)

There are three types of smearing configurations, as mentioned earlier. They are named either "AllJERNP", "FullJER", or "SimpleJER". For the first two cases, the
uncertainties smear both (pseudo-)data and MC events. In the latter case of the "SimpleJER", only the MC is smeared. The implications are as follows:
(Pseudo-)data and MC smearing
This is the most correct thing to do, and should be the default for any analysis where the JER is a non-negligible uncertainty.
Shifting a given NP by +1 sigma will correspond with smearing either the (pseudo-)data or MC, while shifting the same NP by -1 sigma will correspond with
smearing the MC or (pseudo-)data.
If the uncertainty for a given component crosses zero, then this will change whether (pseudo)-data or MC is smeared, thus properly retaining the anti-correlated
behaviour implied by the uncertainty, rather than enforcing a correlated behaviour.
MC-only smearing
This is an approximation, and is acceptable for analyses where the JER is a negligible uncertainty.
Shifting a given NP by +1 sigma or -1 sigma will return the same result, where the MC is smeared in both cases by the same factor. The analysis must
therefore manually symmetrize the uncertainty.
If the uncertainty for a given component crosses zero, then this will force a correlated behaviour, thus ignoring the anti-correlation implied by crossing zero. The
analysis therefore is changing the correlation structure of the JER uncertainties.
To repeat, if the JER is a non-negligible uncertainty, you should use the full (pseudo-)data and MC smearing configurations. The MC-only smearing variant is a
simplification for analyses which are not sensitive to the JER.
In some cases, an analysis may be sensitive to the JER, but it may not be possible to smear the data. For example, if the analysis has a very small number of data events,
then smearing the data can lead to arbitrarily large fluctuations that have to deal with the statistics of the sample rather than the JER. In such cases, pseudo-data can be used
instead of data. Examples of pseudo-data techniques and where they are relevant can be found on this twiki.
A detailed description about how to use the fullJER uncertainties can be found in this presenation .
⚠️ For analyses using the fullJER: pay special attention to slides 7-11 of the presentation above where it is explained how to construct the JER systematics in your
analysis from the combination of (pseudo-)data and MC smearing NPs provided by the JetUncertainties tool. To be clear, one should not propagate independently these
NPs but build templates using them.
Using the JetUncertainties tool
Getting the JetUncertainties tool code
The JetUncertainties package and associated tool should already be included in the (Ath)Analysis* release that you are using. In case you are not using such a release,
you likely already know how to check it out. The tool lives in the directory Reconstruction/Jet/JetUncertainties ( link ).
Configuring and initializing the tool
The tool has four mandatory parameters that you must specify:
JetDefinition, a string
AntiKt4EMPFlow for R=0.4 jets built from particle-flow objects
MCType, a string
MC20 or MC21 for full simulation samples
ConfigFile, a string
The name of the config file, including the relevant folders. See above for the available config files.
IsData, a boolean
You can skip this if you only use the JES, but this is a new parameter that is strictly necessary for the JER
This flag should be "true" if you are running over data (or pseudo-data) and "false" if you are running over MC
This has zero impact on the JES uncertainties, but controls how the JER uncertainties are applied
The tool has a few optional parameters that are not normally relevant but which may be useful in specific circumstances:
CalibArea, a string
If the tool default is not pointing to the CalibArea version that you want, you can force the tool to look at a different CalibArea version by setting this flag
Path, a string
If you want to read config files from an area other than the CalibArea, then this option can be specified, pointing to the directory to read from instead. Note that if
the tool fails to find the specified files in this directory, it will fall back on CalibArea.
AnalysisFile, a string
If you are specifying the flavour composition for your analysis, this should be the full path to the relevant root file to read the composition histograms from.
Athena example:
ToolSvc += CfgMgr.JetUncertaintiesTool ("JESProv", JetDefinition ="AntiKt4EMPFlow", MCType="MC20", ConfigFile ="rel22/Summer2023_PreRec/R4_CategoryReduction_

Running the tool on a jet
The JetUncertaintiesTool implements the ASG-specified CP::ISystematicsTool interface in the form of continuous uncertainties. That means that you can request any
variation, rather than just plus or minus one sigma. However, note that assumptions are built into the tool in order to do this. If you request a -4.2 sigma variation, this is just
-4.2 times the one sigma variation. If you wish to use a different scheme, you are recommended to retrieve the shifts directly as mentioned above and proceed from there.
The signatures supported are:
CP::CorrectionCode applyCorrection(xAOD::Jet& input);
CP::CorrectionCode correctedCopy(const xAOD::Jet& input, xAOD::Jet*& output);
CP::CorrectionCode applyContainerCorrection(xAOD::JetContainer& inputs);<br />
As the names imply, the first takes a jet and changes the scale, the second creates a new copy of the jet at a new scale, and the third changes the scale of all jets in a given
container. Note that a version of each of the above methods with on extra (final) argument of xAOD::EventInfo exists for supporting rare use cases, as will be discussed later.
The most common example of how to use the tool (retrieving the list of systematics automatically and shifting by +/- 1 sigma) is:
const CP::SystematicRegistry& registry = CP::SystematicRegistry::getInstance();
const CP::SystematicSet& recommendedSystematics = registry.recommendedSystematics();
std::vector sysList = CP::make_systematics_vector(recommendedSystematics);
std::vector::const_iterator sysListItr;
for (sysListItr = sysList.begin(); sysListItr != sysList.end(); ++sysListItr) {
xAOD::JetContainer* jets = ; // Get the jets here or re-set them to the nominal scale (avoid applying systematic variations to an already varied jet)
if (jetUncTool.applySystematicVariation(*sysListitr) != CP::SystematicCode::Ok) {
ERROR("execute()","Cannot configure jet uncertainties tool for systematic");
continue; // skip this systematic
}
for (size_t iJet = 0; iJet &lt; jets.size(); ++iJet) {
if (jetUncTool.applyCorrection(*jets.at(iJet)) != CP::CorrectionCode::Ok) {
ERROR("execute()","Cannot apply systematic variation to the jet");
continue; // skip this jet
}
INFO("Successfully applied systematic variation to the jet");
}
}

Tool requirements and assumptions
For the most part, the above instructions should work without problem for users. However, in some cases, additional user-specified data is required. In particular, the
xAOD::Jet and xAOD::EventInfo objects are expected to contain certain variables. Below is a list of these assumptions:
xAOD::Jet variables:
GhostMuonSegmentCount: The number of muon segments associated to the jet. This should be part of the Jet without any user input, so long as the user has not
removed this information from their xAOD file.
IsBjet: Whether the user considers the jet as a b-jet (true) or light quark/gluon jet (false) for the flavour uncertainties. This is expected to be the most common
reason for the user to modify a jet before asking for its uncertainty. If the user does not specify this variable, it is assumed that it is a light quark/gluon jet, as has
been done in the past. This is generally conservative for b-jets on the per-jet level, but not necessarily once correlations are considered between the flavour and
b-jet terms in events containing both b-tagged and non-b-tagged jets. Profiling may also change this picture. (NOTE: this is to be done using truth-labelling
(PartonTruthLabelID moment) plus any analysis-specific kinematic selections used to define b-jets applied to the nominally calibrated kinematic values.)
xAOD::EventInfo variables:
NPV: The number of primary vertices is expected to be specified within this object. Users should not have to worry about this as it is done automatically, so long
as the user does not specify the EventInfo object directly, and so long as the "PrimaryVertices" collection has not been removed from the xAOD file. For non￾standard use cases, it is important that this variable is set by the user.
Njet: The number of user-selected good jets in the event. This is only necessary for users who provide their own flavour composition files, and divide the
composition in bins of jet multiplicity. If the user is performing such an analysis, they need to fill this variable within EventInfo.
An example of how to set the IsBjet moment :
xAOD::Jet* jet = ; // get the jet you want to modify
bool isBjet = ; // decide whether or not the jet is a b-jet (truth-labelling + kinematic selections)
SG::AuxElement::Accessor&lt;char&gt; accIsBjet("IsBjet"); // char due to limitations of ROOT I/O, still treat it as a boolean value
accIsBjet(*jet) = isBjet;
