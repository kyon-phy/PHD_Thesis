Configuration
The FastFrames configuration file consists of several blocks. Available options
for each block are documented below. Using an option which is not supported
will result in an error.
The options are case sensitive. Example config files can be found in
test/reference_files/configs_run/
and
test/reference_files/config_reading/
.
Command-line options
FastFrames.py
and the helper scripts in
python/
also accept command-line
arguments. Some of these override values from the config file (e.g.
--input-path
,
--ncpus
,
--output-path-histograms
,
--filter-campaigns
,
--no-progress-bar
), while others control how a given run is split or which
subset of samples/regions to process (e.g.
--samples
,
--regions
,
--split-n-jobs
/
--job-index
,
--step
). The most commonly used ones are
introduced in context in the relevant feature pages.
For the authoritative, always-up-to-date list of options for any script, pass
--help
:
python3
python/FastFrames.py
--help
python3
python/produce_metadata_files.py
--help
YAML anchors
FastFrames configs are plain YAML, so you can use standard YAML anchors (
&
)
and aliases (
*
) to avoid repeating blocks. An anchor defines a block to be
reused, and an alias refers back to it:
Defaults
:
&defaults
Company
:
foo
Item
:
123
Computer
:
<<
:
*defaults
Price
:
3000
This is especially handy for sharing variables between analysis regions.
Suppose
Region2
needs everything in
Region1
plus one extra variable, and
Region3
needs everything in
Region2
plus another. Rather than copying lists,
anchor each list and extend it:
Region1
:
Variables
:
&alias1
# anchor for var1 and var2
-
var1
-
var2
Region2
:
Variables
:
&alias2
# anchor for var1, var2 and var3
-
*alias1
# resolves to var1 and var2
-
var3
# extend with var3
Region3
:
Variables
:
-
*alias2
# resolves to var1, var2 and var3
-
var4
Tip
If you use anchors to build helper blocks that are not themselves valid
FastFrames blocks, set
allow_unused_blocks: True
in the
general
block so
FastFrames does not error on the extra top-level keys.
include_file
Note
This is not a standard YAML feature. It is implemented manually by FastFrames.
As config files can become fairly long, FastFrames has added an
include_file
which allows for the inclusion of another YAML file.
If you add this into your config:
# first part of your config
include_file
:
/path/to/included/config.yml
# the other part of your config
then the line
include_file: /path/to/included/config.yml
will get replaced by the content of the included file. If there is any indentation before
include_file:
, this will be automatically added to all included lines. Includes can also be nested.
The path is either absolute or a relative path with respect to the config where you have the
include_file
statement.
Tip
If you need to use this parsing in your own code, you can find the function we use here:
python/fastframes/config/ConfigIncludes.py
