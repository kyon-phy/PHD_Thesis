Automatic Systematics
FastFrames can automatically define systematic variations. Add
automatic_systematics: true
to your
general
block to turn on this feature.
Defining Systematic Uncertainties in the Configuration File
It might be important/convenient to provide a list of systematic uncertainties manually in the config file.
For this, FastFrames provides an option block
systematics
that allows you to manually define systematic variations.
For example the following block:
systematics
:
-
samples
:
[
"ttbar_FS"
]
regions
:
[
"Electron"
,
"Muon"
]
variation
:
up
:
"JET_BJES_Response__1up"
down
:
"JET_BJES_Response__1down"
represents a manual definition of
JET_BJES_Response__1up
and
JET_BJES_Response__1down
systematics.
The up and down variation is not important here, but might be important when producing the TRExFitter config file (if automatic systematics are not switched on).

NOSYS
with
JET_BJES_Response__1up
and
JET_BJES_Response__1down
to define two systematic variations.
This includes the event weights, sumWeights and selections.
You can restrict a given variation only to some regions or samples.
For the list of provided options see the
documentation
.
When automatic systematics are turned on and some systematics are defined in the config file, the definition in the config file will be used in case of identical names as the automatic systematic.
If the systematic variation in the config file does not match any automatic systematic it will still be included as defined in the config file.
Defining Truth-Level Systematics in a Custom Class
Truth-level uncertainties can affect only the event weight, not the event reconstruction.
In order to add truth-level systematic uncertainties, one has to make 3 steps:
Define the alternative weight inside of
defineVariablesTruth
method. Such as:
mainNode
=
mainNode
.
Define
(
"weight_mc_MY_AWESOME_SYST"
,
[](
float
weight_mc
,
float
truth_t_pt
){
return
weight_mc
*
(
1
+
truth_t_pt
/
1e6
)},
{
"weight_mc_NOSYS"
,
"trruth_pt_t"
});
Add it as a systematic uncertainty in customframe (again in
defineVariablesTruth
method):
this
->
addVariableAndEffectiveSystematicsTruth
(
"name of your truth block"
,
"MY_AWESOME_SYST"
,
{
"weight_mc_NOSYS"
});
Define the systematics in your config:
-
samples
:
[
"ttbar_FS"
]
variation
:
up
:
"MY_AWESOME_SYST"
The systematic uncertainty will be normalized to the
NOSYS
sum of weights (unless set otherwise from your config). If you need a different normalization for your custom-code truth uncertainty, the best way to achieve this is to incorporate this directly into the event weight.
